## Maturity terms

| Term | Meaning in this portfolio |
|---|---|
| Completed output | The referenced documentary or experimental output is recorded as completed within its scope. This does not mean the entire project is complete. |
| Accepted / integrated | The reviewed records identify an applicable acceptance or repository integration. Acceptance remains limited to that output. |
| Prototype / synthetic experiment | A bounded implementation or experiment exists, using its stated test inputs and environment. |
| Planned / proposed | A question, architecture direction, instrument, or future work item exists without a claim that its intended outcome has been achieved. |
| Open / not established | Required evidence or disposition is incomplete, unresolved, unsupported, or outside the reviewed material. |

## Supporting capabilities

[Infra Software Factory](../projects/infra-factory.md) has implemented local planning, approval, task-state, checkpoint, recovery, and acceptance controls. Retained records demonstrate planning that stopped before approval, a blocked task recovered and resumed in a fresh process, and a trivial synthetic interactive delivery with passing acceptance checks. These demonstrations were not rerun for the portfolio. They do not establish execution of the stronger current specialist policy on those earlier tasks, general delivery reliability, host isolation, or production security. The current documented process, implementation observations, and historical demonstrations retain separate evidence boundaries.

[Security Assessments](../projects/security-assessments.md) has implemented offline analysis, authorization-record checks, evidence manifests, reporting, and narrowly bounded optional adapters. Its 56 existing synthetic tests passed during preparation of the brief; external tool responses and worker state were simulated. Posture collectors are present but were not run. Governance and cloud review include manual workflows; authenticated cloud collection, broader offensive capabilities, and deployed-worker readiness remain unimplemented or unverified. This evidence does not validate the security of the four research projects.

## Handling stale or conflicting summaries

Some root documents describe an earlier point in a project's development. Later committed design and experiment records were used to qualify those historical summaries. Selected work-item records clarify newer scope, predecessor acceptance, and remaining blockers.

Where a record documents implementation without qualifying system evidence, this portfolio describes a prototype or experiment. Where a study is only registered or its instrument is implemented, this portfolio does not invent a scientific result. Administrative issue state is not treated as a substitute for the applicable acceptance record.

## Limits of this work sample

This repository contains summaries rather than independently reproducible source packages. The four research projects' underlying tests and experiments were not rerun for the portfolio. Only the existing Security Assessments synthetic test suite was rerun for its supporting brief; no collectors, live tools, or new assessments were run. No new benchmark, penetration test, production assessment, security certification, commercial validation, or human acceptance is implied.

An external reader can assess the reasoning and disclosure discipline shown here. Detailed technical diligence would require separately authorized access and review of the underlying evidence.
